# 1: 컴퓨터 하드웨어의 구조와 CPU

---

## 1-1. 컴퓨터 하드웨어의 전체 구조

* 하드웨어의 정의와 구성: 물리적 기계 부품들로 구성되며, 단일 부품 독립 실행이 아니라 부품 간 유기적 협력으로 작동한다.


* 5대 핵심 요소: 입력장치(외부 신호 수용), CPU(두뇌 역할 연산 및 제어), 메모리/RAM(작업 중 데이터 임시 보관, 휘발성), 저장장치/SSD·HDD(대용량 데이터 장기 보관), 출력장치(최종 결과 전달)로 나뉜다.


* 정보 처리 흐름과 병목 현상: 데이터는 입력 -> 처리 -> 기억 -> 출력 경로를 거치며 유기적으로 순환한다. 특정 단계의 지연으로 전체 시스템이 대기하는 병목 현상이 발생할 수 있으므로, 고가 부품 교체보다 병목 지점 해결이 성능 개선에 효과적이다.


* 문서 작성 동작 순서: 키보드 입력 후 CPU가 명령을 처리해 RAM에 임시 적재하며, 저장 명령을 실행해 SSD나 HDD에 기록해야 전원이 꺼져도 데이터가 보존된다.


* 스펙 해석 유의점: 광고의 단일 수치로만 성능을 단순 비교하기보다 아키텍처, 세대, 측정 환경, 실제 사용 목적을 함께 고려해야 한다.


  확인 질문 및 과제:
* 스마트폰 사진 촬영 시 4대 동작 단계 분석: 카메라 센서 빛 감지 및 터치(입력) -> 이미지 프로세서 연산 및 압축(처리) -> 저장장치에 사진 파일 및 메타데이터 기록(기억) -> 디스플레이 화면 표시 및 셔터음 재생(출력).

## 1-2. CPU의 구조와 역할

* CPU의 3대 핵심 역할: 프로그램 명령어를 읽고 해석하는 명령 해석, 데이터 산술 계산과 논리 대조를 수행하는 계산, 타 하드웨어 동작을 통제하는 장치 제어이다.


  CPU 내부 3대 구성 요소:
* 제어장치(CU): 작업 순서를 결정하고 제어 신호를 생성해 시스템 전반을 지휘한다.


* 산술논리연산장치(ALU): 사칙연산(산술 연산)과 참/거짓 판단(논리 연산)을 실제로 수행한다.


* 레지스터(Register): CPU가 당장 처리해야 할 값과 실행 중인 명령어를 일시 보관하는 초고속 임시 기억장치이다.




* CPU 성능 결정 5대 요소: 동작 속도 박자를 주는 클럭, 병렬 처리가 가능한 코어 수, 속도 격차를 줄이는 캐시 메모리(SRAM), 주기억장치(RAM) 대역폭, 소프트웨어의 멀티코어 병렬 최적화 여부이다.


  현대 CPU 핵심 기술:
* 인출·해독·실행 단계를 겹쳐 실행하는 파이프라이닝, 다음 실행 경로를 사전 예측하는 분기 예측이 쓰인다.


* CPU, GPU, NPU가 역할을 분담하는 이종 프로세서 협업 구조를 취한다.


* 작업을 분할·병합하는 오버헤드와 직렬 연산 구간 때문에 코어 수가 2배가 되어도 성능이 단순 2배로 증가하지는 않는다.




  확인 질문 및 과제:
* 12 × 5 계산 예시: 입력 수치가 레지스터에 보관된 후 제어장치의 지시로 ALU가 곱셈을 수행해 60을 도출한다.


* RAM이 필요한 이유: CPU와 속도 차이가 큰 보조기억장치 사이에서 작업 데이터를 미리 올려두어 효율을 얻을 수 있기 때문이다.

## 1-3. 명령어 처리 과정

* 프로그램 실행 원리: 고급 언어 코드는 컴파일을 거쳐 0과 1의 기계어 명령어로 변환되며, CPU는 이를 잘게 쪼개어 빠르게 반복 처리한다.


* 명령어 기본 구조: 수행할 동작을 지정하는 연산 코드(Opcode)와 대상 데이터나 메모리 주소를 지정하는 피연산자(Operand)로 구성된다.


  명령 주기(Instruction Cycle) 4단계:
* 인출(Fetch): RAM의 명령어를 CPU 내부 레지스터(PC -> MAR -> 메모리 -> MDR -> IR)로 가져오고 PC를 갱신한다.


* 해독(Decode): 제어장치가 IR의 명령어를 해석해 피연산자와 메모리 주소를 파악하고 제어 신호를 생성한다.


* 실행(Execute): ALU가 제어 신호에 따라 연산을 수행하거나 데이터를 이동한다.


* 저장(Store): 연산 결과나 상태를 레지스터 또는 메모리에 기록한다.




* 3대 시스템 버스: 데이터 버스(실제 데이터 이동), 주소 버스(메모리 위치 전달), 제어 버스(읽기·쓰기 신호 제어)로 구분된다.


* 파이프라이닝 위험(Hazard): 데이터 위험(이전 결과 즉시 참조), 제어 위험(조건 분기 미확정), 구조적 위험(하드웨어 자원 동시 충돌)이 발생하며 지연, 포워딩, 분기 예측으로 해결한다.


  확인 질문 및 과제:
* 두 수의 덧셈 처리 과정 4단계: 메모리에서 덧셈 명령어 읽기(인출) -> 제어부의 덧셈 해석 및 번지 확인(해독) -> 연산 장치의 계산 수행(실행) -> 결과값 기록(저장).


* 12 + 5 연산 흐름: 메모리 주소에서 R1, R2로 각각 로드(LOAD) -> R1과 R2를 더해 R3에 저장(ADD) -> R3의 결과값 17을 메모리 주소에 기록(STORE).

## 1-4. CPU의 성능을 결정하는 요소

CPU 성능을 결정하는 5대 핵심 요소:
* 클럭(Clock): CPU 동작의 기준 박자를 제공하며, 클럭 수치가 높을수록 단위 시간당 처리 속도가 빨라지지만 발열과 구조적 병목 때문에 클럭 수치와 성능이 완전히 정비례하지는 않는다.


* 코어(Core): 독립적으로 명령어를 실행할 수 있는 핵심 단위이며, 코어 수가 많을수록 여러 작업을 분할해 병렬로 처리할 수 있다.


* 캐시 메모리(Cache): CPU와 주기억장치(RAM) 사이의 현저한 속도 차이로 인한 병목을 줄이기 위한 초고속 메모리(SRAM)이며, 자주 쓰는 데이터와 명령어를 미리 적재해 지연을 줄인다.


* 메인 메모리(RAM): 주기억장치의 대역폭과 용량이 성능에 영향을 주며, 비용과 발열 문제로 고속 SRAM 대신 대용량 DRAM을 사용한다.


* 소프트웨어 병렬 최적화: 프로그램이 멀티코어 환경과 병렬 처리 구조를 지원하도록 설계되었는지에 따라 실제 체감 성능이 크게 좌우된다.




  코어 수와 성능의 한계:
* 코어 수가 2배로 증가한다고 해서 전체 시스템 성능이 단순 2배로 늘어나지는 않는다.


* 작업을 여러 코어로 분할하고 다시 병합하는 과정에서 발생하는 오버헤드, 캐시 및 메모리 대역폭 병목, 병렬화가 불가능한 직렬 연산 구간이 존재하기 때문이다.




  현대 CPU의 성능 향상 기술:
* 파이프라이닝(Pipelining): 명령어의 인출, 해독, 실행 단계를 겹쳐 동시에 진행하여 단위 시간당 처리량을 극대화한다.


* 분기 예측(Branch Prediction): 조건문에서 프로그램이 이동할 다음 실행 경로를 미리 예측해 쉬지 않고 명령어를 사전 인출한다.


* 이종 프로세서 협업: 직렬 처리와 복잡한 제어는 CPU, 대규모 데이터 병렬 연산은 GPU, 신경망 인공지능 가속은 NPU가 역할을 나누어 처리 효율을 높인다.




  확인 질문 및 과제:
* 클럭과 코어 수만으로 CPU 성능을 단정할 수 없는 이유: CPU 내부 아키텍처 세대, 캐시 메모리 크기, 소프트웨어의 다중 코어 최적화 여부, 발열 제어 수준에 따라 실제 연산 처리 능력이 크게 달라지기 때문이다.


* 이종 프로세서(CPU·GPU·NPU) 협업의 필요성: 모든 연산을 CPU 하나로 처리하기보다 작업 특성에 맞게 연산기를 분담함으로써 전력 소비를 줄이고 대규모 연산(그래픽·AI) 속도를 비약적으로 개선할 수 있기 때문이다.

## 1-5. 메인보드와 부품의 연결

* 메인보드의 역할: 각 부품을 물리적으로 장착하고 전원과 데이터 통신을 조율하는 중심 회로기판이다.


* 주요 구성 요소: CPU 소켓, 메모리 슬롯(DRAM 장착), 저장장치 단자, 확장 슬롯(GPU 등), 입출력 포트(USB, HDMI), 칩셋 및 펌웨어(BIOS)로 구성된다.


* 키보드 신호 전달 경로: 키보드 입력 -> USB 포트 -> 메인보드 -> CPU 처리 -> 그래픽 장치 -> 모니터 화면 출력 순으로 이동한다.


  확인 질문 및 과제:
* 부품 호환성 점검 5대 요소: 메인보드와 CPU 소켓 규격 일치 여부, DDR 메모리 세대 및 클럭 지원 범위, 본체 케이스 내부 규격 크기, 파워서플라이 정격 전력 용량, 메인보드 BIOS 펌웨어 버전 확인.

# 2: 메모리와 기억장치 계층 구조

---

## 2-1. 메모리는 왜 필요한가

* RAM의 필요성과 역할: 대용량 저장장치(SSD/HDD)는 CPU 연산 속도에 비해 느리므로, 실행 중인 프로그램과 데이터를 고속으로 다룰 임시 작업 공간이 필요하다.


* 메모리 계층 속도 비교: SSD/HDD(느림) < RAM < 캐시(Cache) < 레지스터(Register)/CPU(빠름) 순으로 속도가 빠르다.


* 책상 비유: 자료 장기 보관 서랍(저장장치), 책을 펼쳐두고 일하는 책상 위(RAM), 손에 쥔 메모지(레지스터/캐시)로 대응된다.


* RAM 증설과 병목: CPU나 저장장치에 병목이 있다면 RAM 용량을 증설해도 체감 성능 향상이 제한적이다.


  확인 질문 및 과제:
* 브라우저 탭을 많이 열면 느려지는 원인: 탭 증가로 작업 공간인 RAM이 포화되어, 속도가 훨씬 느린 보조기억장치와 데이터를 자주 교환하면서 시스템 전반에 병목이 발생하기 때문이다.





---

## 2-2. RAM과 ROM

* RAM(Random Access Memory): 임의 주소 위치에 즉시 접근해 읽고 쓰기가 가능한 주기억장치이며, 전원이 차단되면 데이터가 지워지는 휘발성(Volatile) 메모리이다.


* ROM(Read Only Memory)과 플래시 메모리: 전원이 꺼져도 내용이 보존되는 비휘발성(Non-volatile) 메모리이며, 부팅 시 하드웨어 점검과 초기화를 수행하는 BIOS(펌웨어)를 저장한다. 현대 시스템의 ROM은 플래시 메모리 기반이라 펌웨어 업데이트가 가능하다.


* 부팅 과정: 전원 인가 시 비휘발성 ROM(BIOS)이 하드웨어 점검 및 초기화를 마친 뒤, 보조기억장치에 있던 운영체제(OS)를 RAM에 적재해 시스템을 가동한다.


  확인 질문 및 과제:
* ROM에 대한 오해 바로잡기: 현대 ROM은 플래시 메모리를 채택하므로 데이터를 절대 수정할 수 없다는 생각은 잘못이며, 업데이트가 가능하다.


* 보존 방식별 정보 분류: 부팅 펌웨어와 보관 파일은 비휘발성 저장 매체에 남겨두고, 작업 중 임시 연산 값은 휘발성 RAM에서 관리한다.





---

## 2-4. 기억장치 계층 구조

* 계층 구조 피라미드: 상위부터 레지스터, 캐시, 메인 메모리(RAM), SSD, HDD 순으로 구성된다. 상위로 갈수록 속도가 빠르지만 용량이 작고 비싸며, 하위로 갈수록 속도는 느리지만 저렴하게 대용량 보관이 가능하다.


* 고속 메모리로 통일하지 못하는 이유: 캐시(SRAM)는 복잡한 구조로 인해 고용량화 시 발열과 면적 문제가 크고 비싸며, 고속 기억장치는 휘발성이어서 영구 보관용 비휘발성 장치가 필수적이다.


  확인 질문 및 과제:
* 도서관 비유 정리: 도서관(대용량 저장장치 SSD/HDD), 책상(작업대 RAM), 펼친 책(자주 보는 캐시), 손에 쥔 메모지(즉시 처리 레지스터)로 연결해 이해한다.





---

## 2-5. 메모리 사용과 성능 확인

* 종합 관찰 필요성: 시스템 지연 발생 시 RAM 점유율만 보지 않고 CPU, 메모리, 디스크 사용률을 작업 관리자에서 함께 관찰해야 한다.


* 가상 메모리와 성능 저하: RAM 용량이 포화되면 OS는 보조기억장치 일부를 가상 메모리로 쓰며, 느린 저장장치와의 데이터 스왑으로 인해 디스크 활동이 급증하고 시스템이 지연된다.


* 메모리 사용률에 대한 오해: OS가 성능 향상을 위해 유휴 RAM을 캐시 메모리로 활용하므로 일시적인 높은 점유율이 고장을 뜻하지는 않는다.


  확인 질문 및 과제:
* 문제 확인 및 해결 4단계: 체감 지연 증상 확인 -> CPU·RAM·디스크 지표 동시 관찰 -> 고점유 프로그램 종료 전후 대조 -> 메모리 부족 가상 메모리 병목 여부 최종 판단.

# 3: 보조기억장치, 입출력 장치와 사양 선택

---

## 3-1. 저장장치의 역할

* 비휘발성 영구 저장: 전원이 꺼져도 운영체제, 응용 프로그램, 사용자 문서 데이터를 영구 보관한다.


* 파일 시스템 기능: 파일 메타데이터 관리, 물리적 저장 블록 분할 및 할당, 디렉터리 계층 구조와 읽기·쓰기 접근 권한을 제어한다.


* 파일 저장 및 삭제 원리: 파일 삭제 시 실제 비트 데이터를 즉시 지우지 않고 해당 블록을 '사용 가능한 빈 공간'으로 마킹만 변경하므로, 새로운 데이터로 덮어쓰기 전까지는 복구가 가능하다.


  확인 질문 및 과제:
* 과제 파일 저장 시 3단계 역할 분담: 응용 프로그램(OS에 저장 요청) -> 파일 시스템(메타데이터 구성 및 유휴 블록 탐색·할당) -> 저장장치(지정 블록에 비휘발성 디지털 데이터 기록).





---

## 3-2. HDD와 SSD 비교

* HDD: 플래터와 기계식 헤드로 자성 기록을 수행하며, 저렴한 비용으로 대용량 보관이 가능하지만 탐색 시간이 걸리고 충격과 소음에 취약하다.


* SSD: 플래시 메모리를 사용해 전기적으로 기록하며, 무소음·저발열·고내구성과 빠른 속도를 갖추었으나 용량당 단가가 높다.


* 최적 조합: 운영체제와 핵심 프로그램은 빠른 SSD(C 드라이브)에 설치하고, 대용량 영상과 백업 파일은 저렴한 HDD에 보관하는 것이 가성비 면에서 유리하다.


  확인 질문 및 과제:
* 기기 목적별 스토리지 조합: 대학생 노트북은 휴대성과 속도를 고려해 단일 NVMe SSD 구성이 적합하며, 대용량 영상 서버는 빈번한 시스템 구동용 소용량 SSD와 보관용 대용량 HDD를 병용하는 것이 유리하다.

## 3-3. 입력장치의 종류와 원리

* 기본 개념: 문자, 소리, 빛, 물리적 움직임 같은 현실 세계의 아날로그 정보를 컴퓨터가 다룰 수 있는 전기적 디지털 신호로 변환한다.


* 주요 장치별 원리: 키보드는 눌린 키 위치를 문자 코드로, 마우스는 이동을 2차원 좌표값으로 변환하며, 마이크는 소리 진동을, 카메라는 빛의 양을 디지털 데이터로 변환한다.


  확인 질문 및 과제:
* 비대면 온라인 수업 강사의 3대 입력장치: 키보드·마우스(문자 입력 및 화면 좌표 조작), 마이크(음성 진동을 전기적 디지털 신호로 변환), 카메라(강사의 시각 빛 정보를 디지털 화소 데이터로 변환).





---

## 3-4. 출력장치의 종류와 원리

* 기본 개념: 컴퓨터 내부의 2진수 디지털 데이터를 인간이 감각으로 인식할 수 있는 화면, 소리, 인쇄물, 진동 등으로 변환한다.


* 주요 장치별 원리: 모니터(RGB 픽셀 명암 및 색상 조합), 스피커(전기 신호로 진동판을 울려 공기 파동 생성), 프린터(잉크·토너의 종이 정착), 햅틱(물리적 진동 피드백).


* 동영상 재생 출력 흐름: 압축 파일 디코딩 -> 프로세서의 영상 프레임 및 음향 신호 분리 생성 -> 모니터 화면 표시와 스피커 음향 동시 출력.


  확인 질문 및 과제:
* 목적별 중요 출력 특성: 게임(부드러운 화면과 입력 지연 방지를 위한 고주사율·빠른 응답속도), 문서 인쇄(정밀한 글씨 표현을 위한 고해상도 DPI와 색 정확도), 정보 접근성(시·청각 제약 보완을 위한 스피커 음성 안내, 화면 자막, 햅틱 피드백).

## 3-5. 목적에 맞는 컴퓨터 사양 선택

* 사양 선택 관점: 최고가 부품의 단순 결합이 최선이 아니며, 주요 사용 목적과 예산에 맞춰 부품 간 병목이 없는 균형 잡힌 사양을 골라야 한다.


* 사양 선택 5단계: 목적 정의 -> 필수 프로그램 권장 사양 확인 -> 예산 설정 -> 부품 간 성능 균형 점검 -> 추후 부품 확장성 검토.


* 용도별 우선순위: 문서 작업(SSD 속도, 배터리, 무게), 프로그래밍(RAM 용량, 멀티코어 CPU), 영상 편집·3D(고성능 GPU, 강력한 CPU, 고속 RAM, 대용량 NVMe SSD).


  확인 질문 및 과제:
* 나만의 사양 선택 실천 과제: 주요 사용 작업 3가지를 정리하고 가용 예산을 책정하며, 작업 특성에 맞춘 CPU·RAM·GPU·저장장치 우선순위와 덜 중요한 기능의 포기 기준을 수립한다.
